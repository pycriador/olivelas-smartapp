> Documentation Standard v1.0


Glossary for **this Documentation Standard’s AI-ready terms**. Project domain glossaries remain separate; follow the same pattern (stable terms, English tokens where machine-readable).

| Term | Definition |
| --- | --- |
| **AI-ready documentation** | Docs structured with identity, metadata, evidence, relationships, and constraints so AI can use them safely — without requiring RAG products |
| **Authority level** | Weight of a source: Authoritative, Verified, Informational, Reference, Historical, Draft, Unknown |
| **Claim** | Atomic assertive statement that can be classified and evidenced |
| **Classification** | Evidence relationship of a claim: Confirmed, Inferred, Proposed, Unknown, Deprecated |
| **Confidence** | Trust in a claim/answer: High, Medium, Low, Unknown — not lifecycle status |
| **Component** | Architectural unit of responsibility |
| **Context pack** | Minimal set of docs/excerpts assembled for a task |
| **Documentation drift** | Docs ≠ authoritative reality |
| **Documentation graph** | Nodes (docs) + typed relationship edges |
| **Evidence** | Artifact that supports or refutes a claim |
| **Freshness** | How current a doc is relative to reality and review policy |
| **Knowledge gap** | Known / Unknown / Assumed / Needs Verification item |
| **Manifest** | Machine-oriented inventory of documents |
| **Progressive context** | Expanding depth from question to answer by levels |
| **Service** | Operable/runnable unit; not identical to component |
| **Source of truth (SoT)** | Authoritative artifact for a class of information |
| **Deprecated (claim)** | Claim withdrawn/superseded; not current SoT |
